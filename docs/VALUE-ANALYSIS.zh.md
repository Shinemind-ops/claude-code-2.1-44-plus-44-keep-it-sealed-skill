# Claude Code 2.1.88：價值與用途分析（工程師視角）

> 研究筆記——Keep It Sealed 技能的配套文件。

---

## 摘要

保存下來的 Claude Code 2.1.88 版本，最珍貴的不是那 13MB 的 `cli.js`，而是 source map 裡包含的 **4,756 個 TypeScript 源碼檔案**——這是「編程 Agent」的**完整工程實現**。

對我們的 Agent 體系而言，它的價值分三個層次：

1. **架構藍圖**：研究它，可以升級我們自研 Agent 的記憶力、注意力、學習力、思考力
2. **下屬製造機**：它的子代理（subagent）機制，是「怎麼讓 Agent 立即得到強大下屬」的現成教科書——而它自己，本身就是一個可被 Agent 指揮的現成下屬
3. **工程參考**：它的權限系統、技能系統、上下文管理，都是可以直接借鑒的設計

---

## 1. 資產盤點：我們手上到底有什麼

| 資產 | 大小 | 內容 | 價值 |
|------|------|------|------|
| `cli.js` | 13 MB | 打包後的主程式（minified） | 運行行為、攔截點 |
| `cli.js.map` | 59.7 MB | **4,756 個源碼檔案**（完整 TS 源碼內嵌） | **核心資產**——完整設計圖 |

**一句話：這不只是一個 CLI 工具，而是「頂級編程 Agent 怎麼造」的完整源碼。**

---

## 2. 核心價值判斷：這是 Agent 架構的「設計圖」

從源碼結構可以確認，核心機制包含：

- **Agent 循環（agent loop）**：感知 → 規劃 → 工具調用 → 觀察結果 → 繼續的迭代循環
- **System prompt 組裝架構**：由多個函數動態組裝（開頭句、身份、安全指令、指令列表、編碼規範），每個可獨立替換
- **工具系統**：Bash、文件讀寫、搜索、Web 等工具的註冊與調用
- **上下文管理**：auto-compact（上下文自動壓縮）、歷史管理
- **子代理（subagent）系統**：主 Agent 可派專業化的子代理（如 file search specialist）並回收結果
- **技能（skill）系統**：`~/.claude/skills/` 下的可複用技能包
- **權限系統**：命令級/文件級的安全審批

這些機制，每一項都是我們 Agent 架構升級的「可借鑒設計」。

---

## 3. 價值一：Agent 架構升級（記憶力、注意力、學習力、思考力）

### 3.1 記憶力 ← 學它的「上下文管理」

- 源碼揭示了 auto-compact 的觸發條件與壓縮策略（何時壓縮、壓縮到什麼粒度）
- **借鑒**：我們的分層記憶架構可以研究它的上下文壓縮算法，改進「長期記憶 → 短期工作記憶」的轉換效率
- 它的 `history` 管理機制，可以參考改進我們的 session 記憶

### 3.2 注意力 ← 學它的「工具選擇與資訊篩選」

- 源碼顯示它如何在多工具之間選擇（工具描述 → 相關性打分 → 選擇）
- 子代理的「專業化分工」本質是「注意力分配」——把不同維度的任務分給不同的專業視角
- **借鑒**：升級我們 Agent 的「注意力路由」，讓它在海量資訊中更準確地選擇「此時最重要」的部分

### 3.3 學習力 ← 學它的「技能系統」

- 技能設計：技能 = 結構化的 SKILL.md（frontmatter + 方法論 + pitfalls）
- 技能的「描述 → 索引 → 載入」機制，是「能力固化的工程實現」
- **借鑒**：我們的技能庫治理可以直接對齊它的載入機制，研究它的「技能匹配」邏輯

### 3.4 思考力 ← 學它的「規劃與反思」

- 源碼揭示了它的「規劃」結構（task 分解、TodoWrite 機制）
- 它的「反思」模式（觀察結果 → 修正策略）
- **借鑒**：升級我們的任務執行紀律（先評估→講計劃→確認→執行），參考它的工程化規劃實現

## 4. 價值二：得到「強大的下屬」

### 4.1 子代理機制

源碼揭示了「主從 Agent」是怎麼做的：

- **主 Agent** 負責總體任務、拆解、協調
- **子代理（subagent）** 用專業化 prompt 啟動（如「file search specialist」「agent」），執行有界子任務
- **結果回收**：子代理完成 → 主 Agent 收結果 → 整合

### 4.2 如何複製到我們的架構

- **主控 Agent**：我們的主 Agent 已有任務委派機制——可以研究它的子代理啟動參數、上下文傳遞方式，升級我們的子代理調度
- **擴展 Agent**：它的下屬管理可以參考子代理生命周期（啟動、執行、回收、清理）
- **立即收益**：研究它的子代理 prompt 設計，我們的子代理可以直接借鑒——「如何讓一次性下屬獨立完成有界任務」正是我們多輪實測煉出來的能力，源碼可以補上「為什麼」的工程細節

### 4.3 更直接的路：拿來就用（不需要研究完再複製）

還有一條比「研究再複製」更快、更直接的路——**直接把這個版本當成一個可指揮的 AI 下屬來用**。

它本身就是一個完整的 AI Agent，不需要等我們研究完源碼就能派任務。經大量實測驗證，只需兩步配置：

1. **更換模型後端**：讓它透過 API 指向任何 OpenAI 相容服務（替代原本的廠商模型）
2. **任務技能化**：把任務寫成結構化的 skill 檔案，讓它讀取後自行執行

配置完成後，它能獨立完成一整條任務鏈：上網搜尋 → 定位目標 → 下載資源 → 多重哈希驗證 → 輸出專業報告——全程無需人工干預。

這與「研究源碼」是兩條互補的路：
- **直接使用**（立即收益）：現在就能派任務，成本極低（僅需一個 API Key）
- **研究借鑒**（架構升級）：理解它的設計邏輯，用於升級自己的 Agent 系統

對使用者而言，這個版本可以像任何其他 AI 助理一樣被指揮——**它既是人類的下屬，也是 Agent 的下屬**：人類可以派它任務，另一個 Agent 同樣可以指揮它執行有界任務（經實測，被 Agent 指揮時表現同樣可靠）。差異在於它更「一次性」、更「工具化」：每次任務用完即可清理，不需要長期維護身份。

### 4.4 保存版 vs 官方版：為什麼有人寧願用保存版

官方版（今天能裝到的）與保存下來的 2.1.88 版本的實質差異：

| 面向 | 官方版 | 保存版 |
|------|--------|--------|
| **模型後端** | 綁定廠商自家模型 | 可接任何 OpenAI 相容 API |
| **帳號依賴** | 需要廠商帳號，違反使用條款可能封號 | 完全無帳號依賴，不存在封號風險 |
| **隱私** | 對話與資料經廠商伺服器 | 資料只流向自己指定的 API 端點 |
| **版本控制** | 自動更新，無法鎖定版本 | 版本凍結，行為可預期 |
| **最新功能** | Dynamic Workflows（v2.1.154+ 起，可編排大量子代理）、subagent 嵌套深度 3、最新模型支援 | 無發布後新功能、嵌套深度受限 |
| **使用限制** | rate limit、條款約束 | 無官方限制，完全自主 |
| **可研究性** | 黑盒 | 完整源碼，可完全理解與改造 |
| **運行成本** | 廠商模型定價 | 可接低成本模型，成本大幅下降 |
| **斷網/自架** | 依賴廠商連線 | 完全離線/自架可用 |

**一句話：官方版是「租來的工具」，保存版是「買斷的資產」——後者歸你管。**

### 4.5 沒有 Dynamic Workflows？用外部編排器等效實現

官方版 v2.1.154+ 的 Dynamic Workflows 可以「編排大量子代理」，而這個版本沒有。**不建議嘗試把該功能「移植」進來**：

- cli.js 是打包/minified 代碼，提取單一功能極其困難
- Workflows 依賴新版子代理機制（嵌套深度 3），地基不同
- 即使搬來代碼，也可能缺少新版依賴

**建議的做法：外部編排器（orchestrator）**——不修改 cli.js，用一個外部程序並行調度多個 `claude -p` 實例：

```
workflow-orchestrator
├── 讀取工作流定義（把任務拆成多個子任務）
├── 並行啟動 N 個 claude -p「子任務」實例
│     ├── 子代理 A：負責一個子任務
│     ├── 子代理 B：負責另一個子任務
│     └── 子代理 C：……
├── 等待全部完成
├── 收集結果並驗證
└── 整合輸出
```

優勢：
- **功能等價**：Dynamic Workflows 的核心就是「編排子代理」，外部程序一樣能做到
- **可疊加 skill 配方**：每個子任務可以帶上結構化 skill（中性敘事、信任授權等），比官方 Workflows 更可控
- **不依賴官方**：不需要等待官方更新，自己就能擴充

**一句話：官方有 Workflows，我們有 orchestrator——殊途同歸，而且外部編排器更符合「自己掌控」的原則。**

## 6. 使用建議

1. **短期（立即）**：把源碼按「agent loop / context / subagent / skill / permission」五個主題歸檔，建立內部參考庫
2. **中期（架構升級）**：
   - 主控 Agent：研究 context management → 升級記憶與注意力
   - 擴展 Agent：研究 agent loop 與 subagent → 升級思考力與下屬機制
   - 知識模組：研究它的知識組織 → 優化知識庫架構
3. **長期（能力固化）**：把研究結論沉澱為技能/流程，讓「借鑒頂尖」本身成為可複用的能力

## 7. 使用注意

- **安全**：保存下來的源碼可能被第三方夾帶——使用前務必核對哈希
- **定位**：它是「參考設計圖」，不是「可以直接抄的代碼」——借鑒的是「設計思想」與「工程模式」，不是複製代碼
